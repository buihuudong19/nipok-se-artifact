# Release notes, version 3.1 (draft)

Status of this draft: the changes below are in the tree. Three things remain before the release, and only the
authors can do them; they are listed under "Before the release".

## Changes since 3.0

### Documentation and numbering

- `docs/paper-map.md`, `formal/README.md`, the three `MAPPING.md` files (template and results copy),
  `experiments/r1-c8-conformance/README.md` and the header of `run-conformance.sh` carry the table, figure and
  section numbers that the manuscript prints. Version 3.0 used the numbering of an earlier draft. The numbers are no
  longer typed: `docs/numbering.json` maps each object to its LaTeX label and printed number, and
  `docs/renumber_paper_map.py` writes them (`--aux`, `--supp-aux` read the numbers from a LaTeX build; `--check`
  verifies). File names, script messages and generated reports keep the names of version 3.0;
  `docs/paper-map.md`, section "Numbering", gives the correspondence.
- `formal/README.md` states what each tool establishes and what it does not, in the terms of the paper. The sentence
  "each of which discharges what the tier above it assumes" is withdrawn.
- `formal/cryptoverif/nipok.cv`, header comment: the bound is the one CryptoVerif prints,
  Psign(time_1, N) + 0.5 * N2^2 / |nonce|. Model code unchanged.
- `formal/easycrypt/SchnorrFS.ec`: origin (`examples/SchnorrPK.ec` of EasyCrypt) and the MIT notice of EasyCrypt
  added; the Fiat-Shamir bound in the closing comment is the one printed in the paper, and the chain is described
  with its two links that are not mechanized. Code unchanged.
- `loadtest_report.txt` and `c6_loadtest_agg.py`: the note on the CPU per journey at 8 journeys/s no longer says
  "not used in the paper"; the paper uses that column, with the caveat that these are 30-s ladder steps.

### Statistics

- New `analysis/tools/c6_served_ratio.py` (statistical evaluation), run by `generate-results.sh` after the
  aggregation. From `blocks.json` alone it computes the served throughput at the knee and its ratio to the two
  Password configurations, for the 30-s knee steps and for the 60-s runs at 100% of the knee (ratio of medians,
  ratio of geometric means with a 95% confidence interval), and the CPU-per-journey ratios at 16 virtual users and
  at 8 journeys/s. It appends a section to `loadtest_report.txt`, the macros `\LtServed*`, `\Lt*Served*`,
  `\LtCpuRatio*` to `macros_lt_suggested.tex`, and writes `load-test/tables/served_ratio.csv`. The headline range
  of the paper (1.2 to 4.6) is now regenerated by an archived script.
- `c7_tables.py` writes a row for proof generation with a resident witness (the measured value against which the
  row "sealed minus resident" is taken); `c7_table_layout.py` prints it as "Prove, resident witness".

### Figures

- Figures of the paper are drawn at their final size (3.297 in for a column, 6.843 in for the text width) with no
  lettering under 7 pt. In version 3.0 they were 6.4 to 15 in wide and the paper scaled their lettering down to
  2.3 to 5.7 pt.
- `c6_figures.py` (new) draws the three load-test figures from the CSV files of the results;
  `c7_hop_breakdown.py` and `c7_burst_timeline.py` accept `--from-results`; `eval_manuscript.py` accepts
  `SUMMARY_CSV`. Each has a second style, `v30`, that reproduces the layout of version 3.0 from the same values.
  The figures can therefore be drawn again without the raw data.
- `fig8_latency`: the label "100%" stands to the right of the cluster of markers.
- `fig2_pareto_fbc`: the note reads "96-B payload: Schnorr-IZK, NIPoK, Pure-EdDSA" and makes no dominance claim;
  no dash in the lettering; the zoom on the cluster is a strip under each panel, so the ML-DSA-65 point of panel
  (a) is no longer covered.
- Unchanged: `fig4-1_radar_fbc` (see below).

### Formal models (prepared, not run)

- `cryptoverif/nipok-idp.cv`, `proverif/nipok-idp.pv`, `proverif/nipok-e2e-idp.pv`: copies with the prover
  identifier in the signed context. `proverif/mutations/`: four copies of the end-to-end model without the PKCE
  check, the code comparison, the token signature check or the certificate-binding check. `run-3.1.sh` runs every
  model and writes a summary table. None of this has been run: see `formal/UNVERIFIED-3.1.md`.

## Before the release

1. **Fill the table "Tool versions and machine of the published runs"** in `formal/README.md` with the versions
   and the machine of the runs reported in the paper. `cd formal && ./collect-versions.sh` writes everything the
   table needs to `formal/tool-versions-3.1.txt` (versions, machine, one timed run of each model of version 3.0). Running `run-3.1.sh` is optional for this release: the paper
   argues that, each model having a single prover, id_P would be the same public constant in every proof and
   cannot change a query result. If it is run, apply the matching case of `formal/UNVERIFIED-3.1.md`, section 4,
   and replace that file by `results-3.1/summary.md`; if not, `UNVERIFIED-3.1.md` stays as it is.
2. **Fill the EasyCrypt release or commit with which `SchnorrFS.ec` was checked** (line marked "TO FILL" in its
   header). The adapted source is already identified there: the version of `examples/SchnorrPK.ec` written by
   commit 9656af66 (releases r2023.09 to r2026.05); the MIT notice is identical at that commit.
3. **Regenerate the results from the raw data** with the pinned Python packages
   (`experiments/requirements.txt`):
   `C6_DATA=<raw>/benchmark-R1-C6 FORCE=1 experiments/r1-c6-statistical-evaluation/analysis/generate-results.sh`
   and the same for `r1-c7-security-cost-ablation` (`C7_DATA`, `C6_DATA`). This is needed for three items that the
   derived data cannot give:
   - `fig4-1_radar_fbc` (radar): it needs the allocation rates of the JMH result file. It still has the layout of
     version 3.0 (lettering of about 2.3 pt at column width). `eval_manuscript.py` has no final-size layout for it
     yet.
   - Table of the cost of each security operation: the row "Prove, resident witness" appears in
     `table11_c7-ablation*` only after `c7_tables.py` 1.2 has run on the raw data. The files in `results/tables/`
     are still those of version 3.0.
   - The figures of the cost breakdown and the two micro-benchmark figures in `results/` were drawn from the
     derived values (three decimals in ms; six significant digits), not from the raw data. A run on the raw data
     replaces them with files drawn from full precision.
   After the run, `md5sum -c md5sums.txt` in each results directory and `docs/renumber_paper_map.py --check`.
4. Refresh the numbers when the manuscript is final:
   `docs/renumber_paper_map.py --aux <build>/main_rev.aux --supp-aux <build>/supplementary.aux --source "<build>"`.
5. Update `CHANGELOG.md` (move these notes there), the version and date in `CITATION.cff` and in `README.md`,
   and tag `v3.1`.
