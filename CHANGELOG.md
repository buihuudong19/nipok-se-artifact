# Changelog

## 3.0 (revised manuscript)

### Repository layout

- The testbed is one runnable tree, `testbed/`, with the layout of the measurement host. Version 2.0 split the code
  into `implementation/` and `deploy/`, and its scripts assumed the tree at `$HOME/openbanking-ecosystem`; the scripts
  now find their paths from their own location.
- Results are grouped by experiment under `experiments/`: `submission/` (the results of version 2.0),
  `r1-c6-statistical-evaluation/`, `r1-c7-security-cost-ablation/` and `r1-c8-conformance/`.
- The repository keeps the code and the derived results; the raw measurement data are in a separate Zenodo dataset
  record (`docs/reproduce.md`).
- Documentation in `docs/`: `reproduce.md`, `paper-map.md` (replaces `plots/README.md`), `environment.md` (replaces
  `ENVIRONMENT.md`), `secrets.md` and `provenance.md`; a README for the testbed and for every experiment;
  `CITATION.cff`.

### New experiments (Section 6.2 of the revised paper)

- Statistical evaluation, Section 6.2.2: `testbed/bank/run-R1C6.sh` drives six load-test blocks in a Williams order, the
  wide-area sweep over seven mechanisms and the JMH steps (main session with 10 forks, A/B of the fixed-base comb,
  Argon2id sensitivity, JVM control). It adds the Password (OWASP parameters) configuration (`R1C6PhcTool.java`) and
  the extraction of Istio metrics (`istio_hops.py`). Analysis and results: `experiments/r1-c6-statistical-evaluation/`.
- Cost breakdown and operational tests, Section 6.2.3: `testbed/bank/run-R1C7.sh`, the JMH project
  `testbed/bank/benchmark/crypto-jmh-c7`, the probe and burst scenario in `testbed/bank/kubernetes/loadtest/k6-psu-c7`
  and the TLS handshake load test `bench-handshake-load.sh`. Analysis and results:
  `experiments/r1-c7-security-cost-ablation/`.
- Conformance tests, Section 6.2.4: test vectors `nipok-test-vectors-v1.json` and `-v2.json`, the JUnit tests
  `NipokC8Test` and `NipokC8VectorsTest`, two independent Python implementations and `run-conformance.sh` in
  `experiments/r1-c8-conformance/`.

### Prototype changes made during the revision

These changes were deployed before the final campaigns, so the published measurements include them.

- `NipokEncoding` (new): encoding checks of NIPoK. Registration (`PsuRegistrationController`) accepts a public key only
  if it passes the enrollment key check, and login (`NipokAuthenticationProvider`) rejects a non-canonical response
  scalar (`nipok_noncanonical_response`).
- `NipokVerifier`: a verification request without a context is refused (`nipok_context_required`) instead of being
  checked against an empty context.
- `SimulatorWalletProvider`: the key-encryption key is read with an absolute `get`, so concurrent proofs no longer share
  the position of one buffer.
- Authorization server: `IndexedInMemoryAuthorizationService`, a thread-safe, indexed and bounded store, replaces the
  default in-memory store of Spring Authorization Server 1.5.0, which raised `ConcurrentModificationException` under
  concurrent journeys and scanned every stored authorization at each lookup. `ParRequestUriGuard` regenerates a PAR
  `request_uri` that Spring Authorization Server would parse incorrectly at `/oauth2/authorize`.
- TPP: `JarmRoundTripTest` follows the current constructor of `JarmValidator`.

### Security

- Deployment secrets are generated on the deployment host (`testbed/secrets/generate-secrets.sh`) and passed to Helm
  and to the scripts; the repository holds placeholders only. The database passwords, the onboarding token and the
  client secret of the `writer` client published in version 2.0 are no longer used (`docs/secrets.md`).
- `03-deploy-bank.sh` creates the Argon2id pepper secret `psu-pepper` from the generated value and warns when the JARM
  keys are missing; the gateway keystore, absent from version 2.0, is generated by `generate-secrets.sh`.
- `ConsentController` refuses requests when no onboarding token is configured. The legacy OAuth clients `writer` and
  `reader` carry BCrypt hashes of discarded random values, and the application test of the authorization server uses
  its own test-only client secret.

### Code and documentation

- Comments, log messages and console output are in English, and decorative characters were replaced by ASCII. Output
  strings that the analysis scripts parse were kept, and the scripts read recorded files in both wordings.
- `run-R1C6.sh export` and `run-R1C7.sh export` copy the raw data to a configurable `EXPORT_DIR`; `run-R1C7.sh` creates
  the symbolic link of its load harness on first use.
- `testbed/bank/benchmark/crypto-jmh/eval_manuscript.py` is the revised JMH figure script (95% confidence intervals over
  forks).
- The documentation of the authorization server (`docs/jarm.md`, `docs/PSU-MTLS.md`, `docs/ed25519-providers.md`) and
  of the TPP, customer and PSU-mTLS load-test kits was rewritten in English and aligned with the code; for example, the
  TPP serves HTTPS with mutual TLS.
- `formal/`: see "Changes since version 2.0" in `formal/README.md`.

### Removed

- Console logs and node CPU traces of the submitted campaigns (moved to the raw-data archive on Zenodo), backup files,
  build output and development helpers not used for the paper (`docs/provenance.md`).
